# 연말 특가 항공권·호텔 대시보드 디자인 명세 (DESIGN)

- 기준 문서: `docs/SPEC.md` 7장(V1~V7), 8.2절(AC-31~AC-44), `schemas/*.schema.json`, `web/public/sample-data/`.
- 이 문서는 화면 배치, 컴포넌트, 상태, 색상·글자·간격 값, 표기 형식, 접근성 요구사항을 확정한다. 데이터 필드 이름은 스키마와 같다.
- SPEC과 이 문서의 내용이 다르면 SPEC을 우선한다.
- 구현 확인은 10장의 체크리스트(DS-01 ~ DS-36)로 한다.

## 1. 디자인 방향

**이름: 운항 시각표.** 공항 출발 안내판과 인쇄된 시각표의 형식을 기준으로 한다. 화면의 주된 내용은 숫자(가격, 날짜)이므로 숫자를 가장 크게, 자릿수를 맞추어 표시하고 나머지 요소는 최소로 사용한다.

| 원칙 | 적용 |
|---|---|
| 숫자 우선 | 가격은 화면에서 가장 큰 글자다. 모든 숫자에 `font-variant-numeric: tabular-nums`를 적용한다 |
| 선으로 구분 | 영역은 1px 선과 여백으로 구분한다. 그림자, 그라데이션, 배경 이미지, 장식용 일러스트, 이모지를 사용하지 않는다 |
| 강조색 1개 | 특가 표시에만 코발트색(`--deal`)을 사용한다. 그 외 화면은 무채색과 히트맵·차트 색으로 구성한다 |
| 공항 코드 표기 | `ICN`, `DAD` 같은 코드는 고정폭 글꼴로 표시한다. 노선은 `ICN → DAD` 형식이다 |
| 판정 근거 공개 | 특가마다 4개 기준의 해당 여부를 같은 형식으로 표시한다(5.3절 기준 칩) |
| 색상 외 수단 병행 | 상태, 특가, 가격 수준은 색상과 함께 아이콘 또는 문구로 표시한다 |

사용자는 대부분 텔레그램 알림의 링크를 휴대전화에서 눌러 이 화면을 연다. 따라서 첫 화면(모바일 기준 약 640px 높이) 안에 수집 상태 1줄과 첫 번째 특가의 목적지·가격·일정이 표시되어야 한다.

- L 구간의 열 비율은 왼쪽 7 : 오른쪽 5, 열 간격 32px이다(`grid-template-columns: minmax(0, 7fr) minmax(0, 5fr)`).
- 오른쪽 열은 `position: sticky; top: 16px; max-height: calc(100vh - 32px); overflow-y: auto`로 설정한다.
- L 구간에서 머리글은 제목과 수집 상태 줄을 한 줄에 좌우로 배치한다. S·M 구간에서는 두 줄이다.
- 페이지 전체에서 가로 스크롤이 발생하지 않아야 한다. 가로 스크롤은 지역 필터 줄과 표 영역 내부에서만 허용한다(AC-41).

### 2.3 목적지 선택 동작

- 선택된 목적지는 1개다. 초기값은 다음 순서로 정한다.
  1. 주소의 `#dest={코드}`에 해당하는 목적지
  2. `active` 알림 중 첫 번째 알림의 목적지
  3. `best`가 있는 목적지 중 최저가 목적지
- 목적지를 선택하는 방법은 3가지다: 표의 행, 특가 카드의 "날짜별 가격 보기" 버튼, 상세 영역의 목적지 선택 상자.
- 선택하면 주소의 해시를 `#dest={코드}`로 변경한다(`history.replaceState`). 페이지 이동은 발생하지 않는다.
- S·M 구간에서 표의 행이나 카드 버튼으로 선택하면 상세 영역 제목으로 스크롤하고 제목에 포커스를 설정한다. 상세 영역 제목 옆에 "목록으로" 버튼을 표시하며, 누르면 표의 해당 행으로 스크롤하고 그 행에 포커스를 설정한다. L 구간에서는 스크롤하지 않고 "목록으로" 버튼도 표시하지 않는다.
- `prefers-reduced-motion: reduce`이면 스크롤을 애니메이션 없이 즉시 처리한다.

## 3. 디자인 토큰

CSS 사용자 정의 속성으로 `:root`에 정의한다. 다크 모드는 `@media (prefers-color-scheme: dark)`에서 같은 이름의 값을 바꾼다. 화면에 모드 전환 버튼은 두지 않는다. `<meta name="color-scheme" content="light dark">`를 추가한다.

### 3.1 색상

대비 값은 WCAG 2.x 명도 대비 계산 결과다(괄호 안은 비교 배경).

| 토큰 | 용도 | 라이트 | 다크 |
|---|---|---|---|

| `--border` | 구분선, 카드 테두리(장식) | `#D9D4C8` | `#333C47` |

- `--deal` 계열은 특가 표시와 포커스 표시에만 사용한다. 일반 링크는 `--text` 색에 밑줄로 표시한다.
- 상태 색(`--ok`, `--warn`, `--crit`)은 수집 상태, 오류, "이전 수집 값" 표시에만 사용한다. 가격의 높고 낮음을 표시하는 데 사용하지 않는다.
- 차트 선 2색은 색각 이상 모의 조건의 색차 검사를 통과한 조합이다(인접 색차: 라이트 11.5, 다크 10.0, 기준 8 이상). 색을 바꾸면 다시 검사한다.
- 글자에는 `--series-*` 색을 사용하지 않는다. 범례와 수치는 `--text` 계열로 표시하고 선 모양 표본을 옆에 표시한다.

### 3.2 히트맵 색상 단계

단일 색상(청록) 5단계다. **가격이 낮을수록 배경(`--surface`)과의 대비가 커지는 방향**으로 설정한다. 라이트 모드에서는 가격이 낮을수록 어두운 색이고, 다크 모드에서는 가격이 낮을수록 밝은 색이다.

| 토큰 | 의미 | 라이트 배경 / 글자 (대비) | 다크 배경 / 글자 (대비) |
|---|---|---|---|
| `--heat-1` | 가장 높은 가격 구간 | `#80C1B5` / `#18212B` (7.91) | `#28655E` / `#E9EDF1` (5.73) |
| `--heat-2` | | `#57A89B` / `#18212B` (5.79) | `#3F9084` / `#0E1418` (4.89) |
| `--heat-3` | | `#2B8377` / `#FFFFFF` (4.55) | `#5FAEA0` / `#0E1418` (7.11) |
| `--heat-4` | | `#17665D` / `#FFFFFF` (6.79) | `#86C9BC` / `#0E1418` (9.80) |
| `--heat-5` | 가장 낮은 가격 구간 | `#0A4640` / `#FFFFFF` (10.70) | `#B2E6DB` / `#0E1418` (13.46) |

- 글자색은 단계별로 `--heat-N-text` 토큰으로 정의한다(위 표의 글자 값).
- 가장 연한 단계도 배경과 2:1 이상 대비가 있다(라이트 2.06, 다크 2.43). 따라서 가격이 있는 칸과 없는 칸이 색으로 구분된다.
- 단계 계산(목적지별로 계산, 다른 목적지와 공유하지 않음):
  1. 가격이 있는 칸의 가격을 중복 제거 후 오름차순으로 정렬한다(개수 `n`, 순위 `r`은 0부터).
  2. `n ≥ 5`이면 단계 = `5 − floor(r × 5 / n)`.
  3. `n < 5`이면 최저가부터 차례로 5, 4, 3, 2단계를 지정한다.
  4. `n = 1`이면 5단계다.
- 가격이 없는 칸의 표시는 5.6절에 정의한다.

### 3.3 글자

- 본문 글꼴: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`. Pretendard는 npm 패키지(`pretendard`)의 가변 글꼴 파일을 빌드에 포함한다. 외부 CDN에서 읽지 않는다. `font-display: swap`.
- 코드 글꼴(공항 코드, 실행 ID): `ui-monospace, "SF Mono", Menlo, Consolas, monospace`.
- 숫자: 전체 문서에 `font-variant-numeric: tabular-nums`.

### 3.4 간격·모양

| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-1` ~ `--space-8` | 4, 8, 12, 16, 20, 24, 32, 48px | 모든 여백은 이 값만 사용 |
| 영역 사이 | 32px (L: 48px) | 2.1절 영역 간격 |
| 카드 안쪽 여백 | 16px (M·L: 20px) | 특가 카드, 상세 영역 |
| `--radius-s` | 4px | 칩, 히트맵 칸, 버튼 |
| `--radius-m` | 8px | 카드, 표 영역, 안내 표시줄 |
| 선 두께 | 1px (`--border`) | 구분선. 영역 제목 위에는 2px `--text` 선 |
| 누르는 요소 최소 크기 | 44 × 44px | 버튼, 행, 칩, 선택 상자. 히트맵 칸은 높이 40px + 간격 4px |
| 포커스 표시 | `outline: 2px solid var(--deal); outline-offset: 2px` | `:focus-visible` 전체 |
| 전환 시간 | 120ms, `ease-out` | 배경색·테두리색 변경에만 적용. `prefers-reduced-motion: reduce`이면 0ms |

- 영역 제목 형식: 제목 위 2px `--text` 선, 선 아래 12px 여백, 제목 오른쪽에 건수나 보조 정보를 `--text-2`로 표시한다(예: `오늘의 특가  2건`).
- 그림자(`box-shadow`)는 포커스 표시와 히트맵 선택 표시 외에는 사용하지 않는다.

## 4. 표기 형식

| 대상 | 형식 | 예 |
|---|---|---|
| 가격 | 천 단위 쉼표 + `원` | `338,000원` |
| 가격(히트맵 칸) | 만원 단위, 소수 1자리(천원 미만 반올림). 범례에 `단위: 만원` 표시. 정확한 금액은 선택한 칸 정보와 접근성 이름에 표시 | `33.8`, `177.9` |
| 가격(차트 축 눈금, 선 끝 표기) | 천 단위 쉼표, `원` 생략. 축 위쪽에 `원` 표시 | `340,000` |
| 날짜 | `M/D(요일)` | `12/21(월)` |
| 일정 | `출발일 ~ 귀국일 · N박` | `12/21(월) ~ 12/25(금) · 4박` |
| 일정(표, 좁은 공간) | `M/D 출발 · N박` | `12/21 출발 · 4박` |
| 시각 | `M/D HH:mm` (24시간제, KST) | `11/19 09:24` |
| 시각(차트 축) | `M/D` | `11/5` |
| 비행 시각 | `HH:mm` | `18:40` |
| 소요 시간 | `N시간 N분`(60분 미만이면 `N분`, 분이 0이면 `N시간`) | `4시간 55분` |
| 수집 소요 시간 | 초 단위 값을 `N시간 N분`으로 변환(초는 버림) | 4957초 → `1시간 22분` |
| 경유 | 0회 `직항`, 1회 이상 `경유 N회` | `직항` |
| 비율(판정 문장) | 절댓값 + `% 저렴`, 소수 1자리 | `20.1% 저렴` |
| 비율(대비 표기) | 부호 포함, 소수 1자리, 음수 기호는 `-` | `+12.8%`, `-10.0%` |
| 평점 | `평점 4.3` (소수 1자리) | `평점 4.3` |
| 노선 | `{출발 코드} → {도착 코드}`(코드 글꼴) | `ICN → DAD` |
| 목적지 | `{city_ko} ({country_ko})`. 국내는 도시만 | `다낭 (베트남)`, `제주` |
| 값 없음 | `-` 또는 정해진 문구(각 컴포넌트 참조) | `가격 없음` |

- 가격은 `new Intl.NumberFormat("ko-KR").format(n) + "원"`으로 만든다. SPEC 7장과 AC-43이 `338,000원` 형식을 지정하므로 `₩` 기호는 사용하지 않는다.
- 연도는 표시하지 않는다. 귀국일이 2027년이어도 `1/3(일)`로 표시한다.
- 데이터의 시각 문자열은 모두 `+09:00`이다. 기기 시간대와 관계없이 KST로 표시한다(`Intl.DateTimeFormat`의 `timeZone: "Asia/Seoul"` 지정 또는 문자열의 날짜·시각 부분을 직접 사용). `YYYY-MM-DD` 날짜는 `new Date("YYYY-MM-DD")`로 해석하지 않는다(UTC로 해석되어 요일이 달라질 수 있음). 연·월·일을 숫자로 분리해 요일을 계산한다.
- 요일은 `일 월 화 수 목 금 토` 한 글자다.
- 숫자와 단위 사이에 공백을 넣지 않는다(`4박`, `338,000원`, `20.1%`).
- 데이터의 문자열은 HTML로 해석하지 않고 텍스트로 표시한다(AC-42).

## 5. 컴포넌트

각 컴포넌트는 "구성", "상태", "문구"를 정의한다. 공통 상태(데이터 읽는 중, 읽기 실패)는 6장에 있다.

### 5.1 머리글 `AppHeader`

- 구성: 페이지 제목 `연말 특가 항공권`(`--type-title`), 조건 요약 `12/17 ~ 12/30 출발 · 3~7박 · 성인 1명`(`--type-small`, `--text-2`, `latest.json`의 `trip` 값으로 생성), 샘플 표시, 수집 상태 줄.
- 샘플 표시: `index.json`의 `is_sample`이 true이면 제목 오른쪽에 `샘플 데이터` 칩을 표시한다(`--warn` 글자, `--warn-bg` 배경, 1px `--warn` 테두리). false이면 표시하지 않는다(AC-32, AC-33).
- 머리글은 화면 상단에 고정하지 않는다.

### 5.2 수집 상태 줄 `StatusBar` 와 상세 `StatusPanel` (V1)

**상태 줄(항상 표시)**: 버튼 1개로 구성한다(`aria-expanded`, `aria-controls`). 누르면 바로 아래에 상세 영역을 표시하거나 숨긴다.

```
[아이콘] 일부 실패 · 마지막 수집 11/19 09:24 · 실패 목적지 1곳   [▾]
```

| `status.state` | 문구 | 아이콘(16px, 인라인 SVG) | 색 |
|---|---|---|---|
| `ok` | 정상 | 원 안의 체크 | `--ok` |
| `partial` | 일부 실패 | 삼각형 안의 느낌표 | `--warn` |
| `failed` | 실패 | 원 안의 X | `--crit` |
| `stopped` | 수집 중단 | 채워진 사각형(정지) | `--crit`, 줄 전체 배경 `--crit-bg` |

- 마지막 수집 시각: `status.last_run.finished_at`. `last_run`이 null이면 `수집 기록 없음`.
- 실패 목적지: `last_run.failed_destinations`의 개수. 0이면 이 항목을 표시하지 않는다.
- 아이콘과 상태 문구만 상태 색으로 표시하고 나머지 글자는 `--text-2`다.
- 샘플 데이터 예: `일부 실패 · 마지막 수집 11/19 09:24 · 실패 목적지 1곳`(AC-34).

**상세 영역(버튼을 누르면 표시)**: `--surface` 배경, 1px `--border`, 반경 8px.

1. 최근 실행 요약(정의 목록 `<dl>`, S에서는 2열, M·L에서는 4열)

   | 항목 | 값(샘플) | 원본 |
   |---|---|---|
   | 수집 시간 | 11/19 08:02 ~ 09:24 (1시간 22분) | `started_at`, `finished_at`, `duration_seconds` |
   | 조회 | 670건 중 성공 662건 · 실패 8건 (`no_result > 0`이면 `· 결과 없음 N건`을 성공 뒤에 표시) | `queries.attempted`, `succeeded`, `no_result`, `failed` |
   | 봇 확인 응답 | 57건(재시도 59건) | `queries.bot_checks`, `retries` |
   | 생략 | 0건 | `queries.skipped`. 0이면 항목 생략 |
   | 목적지 | 15곳 중 14곳 성공 | `destinations_total`, `destinations_succeeded` |
   | 특가 · 알림 | 특가 2건 · 알림 발송 1건 | `deals_found`, `alerts_sent` |
   | 마지막 성공 | 11/19 09:24 | `status.last_success_at` |
   | 연속 실패 | 0회 | `consecutive_failures`. 0이면 항목 생략 |

2. 실패 목적지: `파리(CDG)`처럼 도시 이름과 코드를 칩으로 표시한다. 칩을 누르면 해당 목적지를 선택한다.
3. `aborted_reason`이 있으면 `--crit-bg` 배경의 한 줄로 표시한다(예: `연속 8건 조회 실패로 실행 중단`).
4. 오류 목록: `last_run.errors`를 종류별로 묶어 건수를 표시하고(`봇 확인 6건`, `네트워크 2건`), 그 아래에 개별 항목을 `목적지 · 일정 · 메시지` 형식으로 표시한다. 10건을 초과하면 10건만 표시하고 `오류 N건 모두 보기` 버튼을 표시한다.

   | `kind` | 표시 문구 |
   |---|---|
   | `bot_check` | 봇 확인 |
   | `network` | 네트워크 |
   | `parse` | 해석 오류 |
   | `hotel` | 호텔 조회 |
   | `telegram` | 텔레그램 발송 |
   | `other` | 기타 |

5. 최근 실행 목록: `status.runs`를 최신순 표로 표시한다. 열은 `시작 시각 | 결과 | 조회 | 특가 | 알림`이다. 조회 열은 `(succeeded + no_result)/attempted`를 표시한다. 표 영역은 키보드 포커스를 받을 수 있고(`tabindex="0"`, `role="region"`), 폭 360px에서는 글자 12px·결과 아이콘 생략으로 5열을 가로 스크롤 없이 표시한다. 결과는 위 상태 표의 아이콘과 문구를 사용한다. 처음에는 10건을 표시하고 `이전 실행 더 보기` 버튼으로 나머지를 표시한다. 샘플에는 `failed` 실행 1건(11/16 14:02, 0/28)이 포함된다.

### 5.3 특가 카드 `DealCard` (V2)

- 데이터: `alerts.json`에서 `status == "active"`인 알림. 표시 값은 `current_fare`를 사용하고 null이면 `fare`를 사용한다.
- 정렬: 가격 오름차순(샘플: 후쿠오카 219,000원, 다낭 338,000원).
- 영역 제목 오른쪽에 `N건`을 표시한다.
- 카드 모양: `--surface` 배경, 1px `--border`, 반경 8px, **왼쪽에 4px `--deal` 선**. 카드 사이 간격 16px.
- 구성(S 구간, 위에서 아래 순서):

```
┃ [특가] 다낭 (베트남)                    ICN → DAD
┃ 338,000원                 직전 알림 359,000원

┃ [ 항공권 검색 ]   [ 날짜별 가격 보기 ]
```

**빈 상태 `DealsEmpty`**: 카드 1개 크기의 영역에 왼쪽 선 없이 표시한다.

- 제목(15px / 600): `현재 특가가 없습니다`(AC-35)
- 보조 문구(13px, `--text-2`):
  - `alerts`가 0건이면 `수집을 시작한 뒤 아직 특가가 없습니다. 특가가 발생하면 텔레그램으로 알림을 발송합니다.`
  - 지난 알림이 있으면 `마지막 특가: {도시} {가격} ({sent_at} 발송)`
- 그 아래에 `현재 가격이 가장 낮은 목적지`라는 소제목과 최저가 하위 3곳을 `도시 · 일정 · 가격` 행으로 표시한다. 행을 누르면 해당 목적지를 선택한다. `best`가 있는 목적지가 없으면 이 목록을 표시하지 않는다.

**M·L 구간**: 카드 내부를 2열로 배치한다(왼쪽: 항공 정보와 판정 근거, 오른쪽: 호텔). 열 사이에 1px `--border` 세로선을 표시한다. L 구간에서 왼쪽 열 폭이 560px 미만이면 1열로 배치한다(컨테이너 쿼리 또는 폭 기준 분기).

### 5.4 목적지별 최저가 표 `DestinationTable` (V4)

- 데이터: `latest.json`의 `destinations[]`.
- 영역 제목 오른쪽: `N곳`(필터 적용 후 개수).

**조작 영역**(표 위, 순서대로)

1. 지역 필터 `RegionFilter`: 칩 버튼 한 줄. `전체`와, 데이터에 있는 지역을 `국내, 일본, 중화권, 동남아, 대양주, 유럽, 미주, 기타` 순서로 표시한다. 칩 문구는 `일본 4`처럼 지역 이름과 개수다. 1개만 선택된다(`aria-pressed`). 선택된 칩은 `--btn-bg` 배경과 `--btn-text` 글자다. S 구간에서 줄이 화면 폭을 초과하면 줄 내부에서 가로 스크롤한다(`overflow-x: auto`, 스크롤 막대 숨김 없음). 칩 높이 36px, 줄의 위아래 여백 4px로 누르는 영역 44px를 확보한다.
2. 정렬 선택(S·M): 기본 `<select>`. 항목은 `가격 낮은 순`(기본), `가격 높은 순`, `목적지 이름순`이다. L 구간에서는 선택 상자를 표시하지 않고 표 머리글의 `목적지`, `최저가` 버튼으로 정렬한다(`aria-sort` 지정, 정렬 방향 화살표 아이콘 표시).
3. `특가만 보기` 체크 상자.

- 가격이 없는 목적지(`best == null`)는 정렬 방향과 관계없이 마지막에 표시한다. 가격이 같으면 `config` 순서(데이터 순서)를 유지한다.
- 필터나 정렬을 바꾸면 `aria-live="polite"` 영역에 `일본 4곳 표시`처럼 결과를 알린다.

### 5.6 히트맵 `PriceHeatmap` (V5)

- 데이터: 선택된 목적지의 `combos[]`. 조건 범위는 `latest.json`의 `trip`(`depart_from`, `depart_to`, `nights_min`, `nights_max`, `return_by`)으로 계산한다. 날짜를 코드에 직접 쓰지 않는다.
- **방향: 행 = 출발일(14행), 열 = 박수(5열).** 모든 화면 폭에서 같은 방향을 사용한다. 열이 5개이면 폭 360px에서도 칸 안에 가격 숫자를 표시할 수 있기 때문이다.
- 소제목: `출발일 × 박수 가격`. 오른쪽에 조회 범위 표기: `조건 안 일정 {조건 안 칸 수}개 중 {가격이 있는 칸 수}개 가격 표시`(13px, `--text-2`). 실제 `combos` 수를 표시하며 `expanded` 값은 사용하지 않는다.

```
            3박     4박     5박     6박     7박
12/17(목) [ 13.1 ][ 14.1 ][  ·   ][ 13.9 ][  ·   ]
12/18(금) [ ...  ]
 …
12/30(수) [ 15.1 ][ 15.0 ][ ╱╱╱ ][ ╱╱╱ ][ ╱╱╱ ]
```

**크기**

| 항목 | 값 |
|---|---|
| 행 머리글(출발일) 폭 | 56px, `12/17(목)` 12px, `--text-2`. 토·일요일은 600 굵기 |
| 열 머리글(박수) 높이 | 24px, 12px, `--text-2` |
| 칸 | 폭은 남은 폭을 5등분(`1fr`), 최소 44px. 높이 40px |
| 칸 간격 | 4px |
| 칸 글자 | 12px / 500, 가운데 정렬, 만원 단위 소수 1자리(`33.8`, `177.9`) |

- 칸 폭 계산(폭 360px): 360 − 32(페이지 여백) − 24(카드 여백) − 56(행 머리글) − 16(간격 4개) = 232px, 5등분하면 46.4px이다. 이를 위해 **S 구간에서는 상세 영역 카드의 좌우 여백을 12px로 적용한다**(다른 카드는 16px).
- 칸에 전체 금액(`1,779,200`)을 표시하면 이 폭에 들어가지 않으므로 칸에는 만원 단위를 사용한다. 전체 금액은 선택한 칸 정보(`ComboDetail`)와 칸의 접근성 이름에 표시한다.
- 히트맵 영역 내부 가로 스크롤은 폭 340px 미만에서만 허용한다.
- 히트맵은 `<table>`로 작성한다. 열 머리글은 `<th scope="col">`, 행 머리글은 `<th scope="row">`다. 가격이 있는 칸은 `<td>` 안의 `<button>`이다.

**칸 종류**

| 종류 | 조건 | 모양 | 조작 |
|---|---|---|---|
| 가격 있음 | `combos`에 해당 출발일·박수 기록이 있고 `price_krw`가 있음 | 3.2절 단계 색 배경, 단계별 글자색, 반경 4px | 버튼. 누르면 선택 |
| 특가 | 위 조건 + `is_deal == true` | 단계 색 배경 + **2px `--deal` 외곽선(`outline-offset: 1px`)** + 오른쪽 위에 6px `--deal` 원(2px `--surface` 테두리). 외곽선이 옆 칸에 가려지지 않게 `z-index`를 높인다 | 버튼 |
| 최저가 | 목적지의 `best`와 같은 출발일·박수 | 가격 글자 700 굵기 + 가격 아래 2px 밑줄(글자색과 같은 색) | 버튼 |
| 조회하지 않음 | 조건 범위 안이지만 `combos`에 기록이 없음(대표 일정 외, 조회 실패, 출발일 경과) | `--surface-sunk` 배경, 가운데에 `·`(`--text-3`) | 조작 불가 |
| 조건 밖 | `출발일 + 박수 > trip.return_by` | 배경 없음, 1px `--border` 점선 테두리, 45도 빗금 무늬(`--border` 색, 6px 간격 `repeating-linear-gradient`) | 조작 불가 |
| 선택됨 | 사용자가 누른 칸 | 칸 안쪽에 2px `--surface` 선과 그 바깥에 2px `--text` 선(`box-shadow: 0 0 0 2px var(--surface), 0 0 0 4px var(--text)`), `aria-pressed="true"` | — |

- 조회하지 않은 칸과 조건 밖 칸은 배경, 테두리, 무늬가 모두 다르므로 색상 없이도 구분된다(AC-38). 샘플 예: 12/30 출발 5박은 조건 밖, 방콕의 대표 일정 외 58칸은 조회하지 않음.
- 가격 있는 칸의 접근성 이름: `12월 21일 월요일 출발, 4박, 338,000원, 평소보다 낮음, 특가`. 수준 정보가 없으면 그 부분을 생략한다. 조작 불가 칸은 `<td>`에 화면 읽기용 문구 `조회하지 않음` 또는 `조건 밖`을 포함한다.

**범례**(히트맵 아래, 13px): 한 줄로 표시하고 폭이 부족하면 줄 바꿈한다.

```
낮은 가격 [■][■][■][■][■] 높은 가격   130,800원 ~ 157,600원
칸의 숫자 단위: 만원. 색은 이 목적지 안의 가격 순위 기준이며 가격 차이의 크기와는 관계없습니다.
[·] 조회하지 않음   [╱] 조건 밖   [◦] 특가   밑줄: 최저가
```

- 색상 표본 순서는 왼쪽부터 `--heat-5` → `--heat-1`이다. 가격 범위는 해당 목적지에서 가격이 있는 칸의 최저가와 최고가다.

**선택한 칸 정보 `ComboDetail`**(범례 아래)

- 초기 선택: 목적지의 `best`와 같은 칸. `best`가 없으면 선택 없음.
- 구성:

```
12/21(월) ~ 12/25(금) · 4박                    338,000원
비엣젯항공 · 직항 · 평소보다 낮음
[특가] 해당 기준: Google 평소 가격, 수집 이력, 최근 60일

```

- 가격은 20px / 28px / 700(`--type-price-l`)으로 표시한다.
- `matched`가 1개 이상이면 `해당 기준: {칩 이름을 쉼표로 연결}`을 표시하고, `is_deal`이면 앞에 `특가` 칩을 표시한다. `matched`가 0개이면 이 줄을 표시하지 않는다.
- `이 일정으로 항공권 검색` 버튼은 `search_url`을 새 창으로 연다(AC-38). 기본 버튼 모양, 높이 44px.

**히트맵 상태**

| 상태 | 조건 | 표시 |

| 기본 | 가격 있는 칸 1개 이상 | 위 구성 |

| 이전 수집 값 | 목적지 `stale == true`이고 `best != null` | 소제목 아래에 `이전 수집 값` 칩과 `11/18 22:14 수집 값입니다.` 뒤에, 목적지가 `status.last_run.failed_destinations`에 있으면 `최근 수집에서 이 목적지의 조회가 실패했습니다.`, 없으면 `최근 수집에서 이 목적지의 가격을 갱신하지 못했습니다.` 표시 |

### 5.7 가격 추이 차트 `PriceTrendChart` (V6)

- 소제목: `가격 추이`.
- 데이터:

| 요소 | 원본 | 의미 표기(범례 문구) |
|---|---|---|
| 수집 이력 선 | `history/{DEST}.json`의 `points[]`(`collected_at`, `price_krw`). `price_krw`가 null인 점은 제외 | `수집 이력(수집 시점의 목적지 최저가)`. 차트 아래에 조회 일정 수에 따라 값이 달라질 수 있다는 안내 문장을 표시하고, `표로 보기`에 `조회 일정 수`(`combos_checked`) 열을 표시한다 |

| 평소 가격 범위 영역 | `best.insight.typical_low_krw` ~ `typical_high_krw` | `Google 평소 가격 범위 365,000 ~ 560,000원` |

- **축은 1개다.** 세로축은 원 단위 가격 하나만 사용하고 두 번째 세로축을 사용하지 않는다.

|---|---|
| 작성 방식 | 인라인 SVG. 폭은 영역 폭 100%, 높이는 S 220px, M·L 260px |
| 가로축 | 시간. 범위는 두 선의 가장 이른 시각부터 `generated_at`까지. 눈금 최대 4개(S) 또는 6개(M·L), `M/D` 형식. 눈금 간격이 글자 폭의 1.5배 + 8px(65px)보다 좁으면 눈금 수를 줄이고(최소 2개), 같은 날짜의 눈금은 1개만 표시한다 |
| 세로축 | 범위 계산: ① 두 선의 최솟값 `lo`와 최댓값 `hi`를 구한다. ② `typical_low_krw`, 기준가가 `lo × 0.75` 이상이면 `lo`에 포함하고, `typical_high_krw`가 `hi × 1.25` 이하이면 `hi`에 포함한다. ③ 위아래에 범위의 8%를 더한다. 0에서 시작하지 않는다. 눈금 4개, `340,000` 형식(만원 단위로 맞춘 값), 축 위쪽에 `원` 표기 |
| 격자선 | 가로 격자선만, 1px `--border` |
| 수집 이력 선 | 2px `--series-own`, 점 사이를 직선으로 연결, 개별 점은 표시하지 않음. 마지막 점에만 지름 8px 원(2px `--surface` 테두리) |
| Google 60일 선 | 2px `--series-google`, 직선 연결, 점 표시 없음 |
| 평소 가격 범위 | `--band` 색 사각형. 세로축 범위를 벗어나는 부분은 그리지 않는다 |
| 기준가 선 | 1px `--text-3` 점선(4px 선, 4px 간격). 세로축 범위 밖이면 그리지 않는다 |
| 선 끝 표기 | 수집 이력 선의 마지막 점 옆에 현재 가격(`338,000`)을 12px / 600 `--text`로 표시. 오른쪽 여백 64px 확보 |

- 평소 가격 범위나 기준가가 세로축 범위 밖이어도 범례에는 항상 값을 표시한다. 기준가가 축 범위 밖이면 범례 문구 뒤에 `(차트 범위 밖)`을 추가한다. 샘플 예: 다낭은 기준가 299,700원이 범위에 포함되어 점선으로 표시된다. 제주는 기준가 75,000원이 두 선의 최솟값 117,800원의 75%(88,350원)보다 낮아 범위 밖이다.
- 범례: 차트 위에 표시한다. 각 항목은 선 모양 표본(24px 선, 영역은 12px 사각형, 기준가는 점선)과 문구로 구성한다. 문구는 `--text-2` 13px이다. S 구간에서는 항목당 한 줄이다.
- 가리킴·터치: 차트 영역에서 포인터의 가로 위치에 세로 기준선(1px `--border-strong`)과 정보 상자를 표시한다. 정보 상자에는 날짜와, 그 날짜에 가장 가까운 각 선의 값을 표시한다(형식: `{M/D} · 수집 이력 {가격}원 · Google {가격}원`). 정보 상자는 `--surface` 배경, 1px `--border-strong`, 차트 영역 밖으로 벗어나지 않게 위치를 조정한다. 터치에서는 누른 위치에 표시하고 차트 밖을 누르면 숨긴다.
- 키보드: 차트는 `tabindex="0"`이고 좌우 화살표 키로 기준선을 수집 이력 점 단위로 이동한다. Escape 키로 기준선을 숨긴다.
- 대체 정보: SVG에 `role="img"`와 요약 `aria-label`을 지정한다(예: `다낭 가격 추이. 수집 이력 43건, 최저 338,000원, 최고 432,700원, 현재 338,000원.`). 차트 아래에 `표로 보기` 버튼을 두고, 누르면 수집 이력을 최신순 표(`수집 시각 | 최저가 | 일정`)로 표시한다. 처음에는 15행을 표시하고 `더 보기`로 나머지를 표시한다.

### 5.9 지난 알림 `PastAlerts` (V7)

- 데이터: `alerts.json`에서 `status`가 `replaced` 또는 `ended`인 알림, 데이터 순서(최신순).
- 영역 제목 오른쪽: `N건`.
- 행 구성(S: 2줄, M·L: 1줄):

```
12/21(월) ~ 12/25(금) · 4박 · 11/17 22:33 발송 · 11/19 09:24 종료
```

| `status` | 칩 문구 | 모양 |
|---|---|---|
| `replaced` | 추가 인하로 대체 | 1px `--border-strong` 테두리, `--text-2` 글자 |
| `ended` | 특가 종료 | 1px `--border-strong` 테두리, `--text-2` 글자 |

### 5.10 안내 표시줄 `NoticeBanner`

머리글 아래에 표시한다. 해당하는 것이 여러 개이면 아래 표의 순서대로 모두 표시한다. 각 줄은 아이콘 + 문구이고 반경 8px, 안쪽 여백 12px이다.

| 순서 | 조건 | 색 | 문구 |
|---|---|---|---|
| 1 | `status.state == "stopped"` | `--crit` / `--crit-bg` | `수집이 중단된 상태입니다. {consecutive_failures}회 연속 실패했습니다. 마지막 성공: {last_success_at}. 아래 가격은 그 시점의 값입니다.` (`last_success_at`이 null이면 `마지막 성공: 없음.`까지만 표시) |
| 2 | `status.state == "failed"` | `--crit` / `--crit-bg` | `최근 수집이 실패했습니다. 마지막 성공: {last_success_at}. 아래 가격은 그 시점의 값입니다.` (`last_success_at`이 null이면 마지막 문장 생략) |
| 3 | `is_sample == false`이고 현재 시각 − `index.generated_at` ≥ 14시간 | `--warn` / `--warn-bg` | `마지막 수집 후 {N}시간이 지났습니다. 표시된 가격은 현재 가격과 다를 수 있습니다.` |
| 4 | `is_sample == true` | `--warn` / `--warn-bg` | `샘플 데이터를 표시하고 있습니다. 실제 수집 결과가 아닙니다.` |

- `last_success_at`이 null이면 `마지막 성공: 없음`으로 표시한다.
- 3번의 14시간은 수집 주기(최대 간격 11시간)에 수집 소요 시간을 더한 값이다. `N`은 버림한 정수다.
- `state == "partial"`은 안내 표시줄을 표시하지 않는다. 상태 줄과 표의 `이전 수집 값` 칩으로 표시한다.
- 1·2번은 `role="alert"`, 3·4번은 `role="status"`다.

## 8. 구현 참고

- 색상, 글자 크기, 간격은 3장의 토큰으로만 지정한다. 컴포넌트 CSS에 색상 값을 직접 쓰지 않는다.
- 차트 라이브러리 선택은 프런트엔드 담당이 정한다. 5.7절의 규격(축 1개, 선 두께, 범례, 가리킴 정보, 표로 보기, 상태)을 충족해야 한다. 직접 SVG로 작성해도 된다.
- 히트맵은 CSS Grid 또는 `<table>` + `table-layout: fixed`로 작성한다. 캔버스로 작성하지 않는다(칸마다 버튼과 접근성 이름이 필요함).
- 이미지 파일(사진, 일러스트, 국기)을 사용하지 않는다. 파비콘은 단색 SVG 1개만 사용한다.
- 조직 지침의 저작권 문구는 이 문서와 화면 규격에 포함하지 않았다. 개인 프로젝트 사이트에 표기할지는 사용자 확인이 필요하다.
